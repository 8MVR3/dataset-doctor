# dataset-doctor

CLI-инструмент, который проверяет датасет для детекции в формате YOLO перед обучением и выдаёт HTML-отчёт: ошибки разметки, битые файлы, дубли и почти одинаковые кадры в разных выборках, поворот по EXIF, дисбаланс классов.

## Структура

- `dataset_doctor/loader.py` — находит выборки по `data.yaml` (Ultralytics и Roboflow) или по папкам `images/train` + `labels/train`, `train/images` + `train/labels`; сопоставляет фото и разметку, читает рамки. Полигоны сегментации переводит в описывающие прямоугольники.
- `dataset_doctor/checks.py` — все проверки. Каждая возвращает `Finding` с уровнем (`critical`, `warning`, `info`), объяснением `what`, советом `fix` и до 8 примеров `Example`. Здесь же `plural()` для правильных окончаний и dHash для похожих кадров.
- `dataset_doctor/report.py` — HTML-отчёт: один самодостаточный файл, картинки встроены base64, без внешних шрифтов и скриптов.
- `dataset_doctor/cli.py` — командная строка и выгрузка в JSON.
- `tests/test_checks.py` — тесты на синтетических датасетах, которые создаются прямо в тесте.
- `docs/report.png` — скриншот отчёта для README.

## Команды

```
pip install -e .
pytest
python -m dataset_doctor путь/к/data.yaml --out report.html
python -m dataset_doctor путь/к/data.yaml --fail-on-critical   # код 1 при критичных проблемах
```

## Правила

- Python 3.9+. Зависимости только Pillow и PyYAML. Без numpy, OpenCV и прочих тяжёлых библиотек: инструмент должен ставиться за секунды.
- Все тексты для пользователя на русском и простыми словами. У каждой находки обязательно есть «что это значит» и «что сделать». Числа с существительными через `plural()`.
- `critical` — то, что ломает обучение или делает метрики нечестными; `warning` — стоит исправить; `info` — к сведению.
- Похожие кадры ищутся через dHash с корзинами по 8 бит: не сравнивать все пары напрямую, на больших датасетах это слишком медленно.

## Как добавить новую проверку

1. Написать её в `run_checks` в `checks.py` и вернуть `Finding` через `add(...)`.
2. Добавить в `tests/test_checks.py` датасет, где эта проблема есть, и проверить, что код находки появился. Отдельно убедиться, что на чистом датасете она не срабатывает.
3. Дописать проверку в список в README.
4. Если меняется вид отчёта, открыть его в браузере и обновить `docs/report.png`.

## Перед коммитом

- `pytest` проходит.
- Прогон на реальном датасете работает, отчёт открывается.
- В репозиторий не попадают отчёты, датасеты и `__pycache__` (см. `.gitignore`).
